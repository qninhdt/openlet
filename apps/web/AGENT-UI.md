# Agent chat, Overview and Activity

The UI extends the OpenBot-derived shell and its semantic shadcn tokens. It has two data modes: an interactive local preview without Clerk configuration, and authenticated Leta API data when `VITE_CLERK_PUBLISHABLE_KEY` is set. `VITE_API_BASE_URL` selects the gateway origin; an empty value uses the current origin. The gateway must accept that Clerk instance's tokens and allow the web origin when deployed separately.

## Navigation and permissions

Editor-shaped tabs appear in this order: agent name, Overview, Activity, Box. Chat contains only messages sent by the current user and deliveries explicitly addressed to that user. Assistant activity notes and tool calls do not become private chat messages. Overview shows the public agent profile and a **For you** section containing questions/requests addressed to the current user. Settings opens the existing modal.

Activity and its Inbox panel require the agent's `manage` capability. A workspace owner does not automatically own or manage every agent. The server enforces this boundary on inspection, settings, schedules, requests, history, runs and streams; hiding a tab is not the permission check. Request answers still require the exact recipient. Incoming request APIs remain available to workspace participants even when they lack agent chat access.

The runtime retains one inbox/checkpoint per agent. Chat presentation does not create a separate runtime or memory for each human. Private transcript filtering does not isolate the agent's shared context or storage between requesters.

## Chat and requests

Messages keep content-sized bubbles and the existing agent colors. Reply and menu buttons sit beside the bubble: to the left of one's own messages and to the right of agent messages. They appear on hover, keyboard focus or an open dropdown. Right-click exposes the same supported actions. Both chat surfaces reuse the action primitives.

Reply quotes sit above the composer. A pending Questions/Requests queue opens a popup above the composer on desktop and a drawer on mobile. It supports text, single choice and multiple choice questions. Chat drafts, reply selection and each request's answers are independent. Closing the popup keeps the request pending; sending chat does not submit an answer. Answer/allow/decline actions wait for server confirmation. Activity has a disabled composer saying “You can’t send messages here.”

## Activity and Inbox

The Activity timeline renders typed input snapshots, tool calls/results and internal notes. Human/agent notifications, inbox batches, schedule deliveries and question/access decisions have distinct content. Inputs align right, with an ordinary theme surface and a **2px agent-colored border**. Compaction is a separator labelled **Compacted**; clicking it reveals the summary.

Inbox is the default right-hand tab on Activity. It combines conversation summaries, questions/requests and schedules with search, type filtering and unread-by-agent state. Inspecting a conversation never marks it read. Schedule details allow title/instruction edits and pause/resume; request inspection allows cancellation, without answering for another recipient. The panel always retains a nonclosable Files tab; Activity adds Inbox alongside its closable file tabs. The panel is available only on Agent pages, never Box.

Tool renderers use versioned runtime artifacts, not parsed/clipped JSON history previews. Request creation cards retain their historical snapshot; later answers cannot rewrite that snapshot. Older records without typed artifacts show the recorded text. File search retains actual excerpts, schedule timing comes from actual calendar/interval values, and execute omits the cwd/exit-code metadata row.

Chat and both Activity renderers share transcript padding/container geometry through `transcriptStyles`. Resize mirrors panel widths into header CSS variables; only crossing the compact-sidebar threshold updates shell state. Pixel-by-pixel widths do not pass through the agent context.

Keep the existing 280px agent list (88px compact), 38px header, resizable 360px context panel and mobile panel behavior. Action results fit their contents; code/diffs use OpenBot's wide-message formula, `min(100%, max(720px, 70%), 1200px)`. Tool bodies have natural height and no nested vertical scroll viewport. Wide code/tables scroll horizontally. Collapsed content retains 12px separation from its trigger.

## Agent organization and reactions

The Search `+` menu creates an agent or an inline folder. Agent creation reuses the settings form and waits for asynchronous provisioning before selecting the new agent. An empty live workspace also provides the first-agent creation action. Pins are an avatar grid and do not duplicate agents in the list. Folder headers retain OpenBot’s flat section treatment, parent/name paths, inline rename/create, collapse, move and delete actions. Drag/drop and context menus move/reorder agents and folders; nesting is limited to three levels. Deleting a folder keeps its agents and reparents its children. Folder editing temporarily expands a compact sidebar.

Organization is personal to the current actor and workspace. Live `GET/PUT /v1/workspaces/{workspace}/letas/sidebar` persists one layout with an optimistic revision; stale writes return 409 and reload canonical state. Its `/events` stream is personal. Layout endpoints reject references outside accessible workspace agents. Preview preferences use actor/workspace-scoped localStorage.

The sidebar follows OpenBot's pinned strip → Unread → flat folder sections. Rows are 62px with 46px avatars; pinned tiles are 72×102px with 56px avatars. Rows include a truncated preview, title badge and timestamp. Unread chats leave their assigned folder temporarily; pinned chats retain their tile and avatar badge. The open unread row stays under the pointer until the pointer leaves. Folder rows and Storage sidebar items have a 4px gap; Unassigned uses a muted heading. Empty folders remain available as drop targets.

Unread here means an addressed assistant delivery the current human has not read, independently of the agent's Inbox read state. Directory responses include a private chat preview, timestamp and unread count. `PUT .../messages/read` accepts a `through` assistant delivery ID and marks only that recipient's messages up to that boundary. A focused, visible Chat tab acknowledges its loaded deliveries; merely inspecting Activity or Overview does not. Other tabs recover counts through the existing five-second directory polling. Preview read markers persist per actor/workspace and load synchronously to avoid overwriting another chat's markers on first mount. Migration `0004_chat_read.sql` is required before deploying the updated API; existing deliveries begin unread.

Chat uses OpenBot’s six common emoji, expandable picker and matching context submenu. Each actor has one reaction per message; choosing another replaces it, selecting the same one removes it. Reaction badges sit at the opposite bubble edge and reserve space underneath. Rows reserve 24px below reacted bubbles so the 18px anchor offset plus 3px ring stays inside the scroller item’s `content-visibility` paint boundary. Their surface uses `muted`; the separating ring uses the chat canvas token `sidebar`, avoiding the dark background patch. User mutation requests are serialized per target. `PUT .../messages/{user|assistant}/{message}/reaction` is private-conversation scoped and idempotent; the role keeps incoming/outgoing UUIDs distinct.

The only new agent tool is `inbox_react(message, emoji, action)`; there is no emote message/tool. It targets a received ordinary message by inbox sequence. Agent-to-agent feedback follows the existing communication graph. Canonical reactions appear in Chat, Inbox and typed Activity inputs; `inbox_react` has an emoji/quote renderer rather than JSON.

A reaction to an agent-authored message atomically writes a typed `reaction` input with `silent=true` into the existing durable inbox. It updates UI over the existing Redis/SSE streams immediately, but starts no Temporal workflow, never advances the workflow’s admitted wake sequence, and does not enter a running model step by itself. Middleware includes a bounded silent prefix only alongside new ordinary input; separate normal/silent checkpoint cursors prevent a quiet backlog being skipped. Explicit `inbox_list`/`inbox_read` remain available to both root and child agents; explicitly read silent inputs are excluded from later automatic injection. Repeated reaction changes in a batch present only the latest value to the model, while typed snapshots retain prior changes as superseded. Reactions to human-authored messages update their badges without creating self-notifications.

Migration `0003_agent_organization_reactions.sql` adds the layout, reaction and typed/silent input data without rewriting existing messages. Run the normal database migrations before deploying the new API/runtime.

## API and realtime

`agent-api.ts` describes browser DTOs; `agent-live.ts` handles scoped TanStack queries and authenticated SSE. Cache/session scope includes actor, workspace and agent. Actor changes clear cached data and remount interaction state. The frontend uses the gateway's verified identity, never client-supplied actor headers.

The existing Leta API, Redis and SSE provide realtime updates; no additional chat service is introduced. Private `/messages/events` streams contain only that recipient's snapshot/resource notifications. Owner `/events` streams carry internal activity. SQL remains canonical. Notifications trigger debounced query refresh; reconnect, trim resync and a 30-second refresh recover state. A Redis notification failure does not repeat the durable mutation. Streams recheck authorization periodically and before the initial snapshot. This is best-effort push, not guaranteed push or an exactly-once delivery claim.

Activity deltas are agent/run scoped, bounded, and ignore a reconnect delta without a start. Committed history replaces provisional content by stable identity. Private chat uses committed addressed messages, never raw model tokens. Reply references include the message role to distinguish UUID collisions across incoming and outgoing tables. Migration `0002_chat_reply_role.sql` adds reply role and schedule-title snapshots without dropping existing records.

Activity uses assistant-ui `MessagePrimitive.GroupedParts` and `groupPartByType` to put adjacent provider reasoning and tool calls in one shared collapse, preserving their interleaved order. Reasoning is plain muted Markdown without its own heading, icon or collapse; tool details keep their custom renderers. Text answers stay outside the process collapse, and human question/request tools stay standalone. This applies to Leta/Leti preview, committed history and `REASONING_MESSAGE_*` deltas. The live adapter rebuilds assistant turns from ordered history entries, stopping at input, compaction, final-note and run/agent boundaries; canonical entries replace matching provisional parts, while original entry/result IDs remain available for full-detail loading. The runtime reads LangChain's standard reasoning blocks and LiteLLM's readable thinking text; signatures, redacted blocks and encrypted reasoning are not projected. Reasoning and answer deltas remain separate even when they share a message ID, and consecutive model messages use distinct identities. History saved before this projection existed has no retroactively reconstructed reasoning. Private chat never renders internal reasoning.

## Preview and current limits

The preview contains 15 addressed messages per agent, two pending requests, and four multi-turn Activity scenarios covering all tools plus batch/notification/reaction/schedule/decision/compaction inputs. Preview mutations last for the mounted session; pins, folder assignments and their order persist per actor/workspace in localStorage. Newly created preview agents persist in the preview directory. Reaction changes queue silently in Inbox and enter Activity when the next ordinary chat message is sent. Reload resets synthetic messages/files.

The Agent panel and Storage page use the same StoragePage browser and FileViewer/editor, including drag/drop uploads, moves, context menus, selection, all three display modes and Markdown/CSV preview. Authenticated files resolve storage/node IDs through LetFS; demo files use IndexedDB. One workspace-scoped file-session map retains drafts, Preview/Code and scroll state across page/panel switches. Closing dirty tabs requires confirmation. No synthetic file is substituted for a live path. The authenticated browser flow still needs verification against a deployed Clerk/gateway setup. Mobile checks cover browser viewport behavior, not a physical device keyboard. A local agent-switch latency measurement is recorded below; no production load test has been performed.

## Box and Leti identity

Schedule navigation is replaced by **Box**. Its sidebar contains All and the current workspace's manageable Leta agents. The same read-only canvas also appears in each Leta's Box tab, scoped to that Leta. It uses React Flow for pan, zoom, fitting and grouped nodes; node cards follow OpenBot's diagram/avatar/scheduler patterns and semantic shadcn colors. Boxes are framed in their Leta's color. Solid unarrowed links show bidirectional communication permissions, including Leta to each box representative; dashed arrows show scheduled deliveries, not workflow sequence. Collapsing a box hides its members and retargets external links to the frame. The initial desktop view fits one Leta's team to retain readable text; Fit boxes offers the complete graph. Mobile starts at full card size in a single column and supports panning.

Leti cards show **name, then title**, matching Leta. Clicking one opens a closable editor-style tab in the main panel, using the shared Activity/tool/reasoning/compaction renderer and that Leti's Inbox panel. Query and SSE reducer scopes include the child ID; child Activity does not subscribe to or acknowledge the human's private chat. Closing the selected child tab returns to Box. Existing file tabs still use the right panel. In preview, each Leti has its own illustrative timeline; tab scroll position is not saved independently.

Migration **0005_agent_identity.sql** adds `agents.title`, `agents.appearance` JSONB and `runs.heartbeat_at`. Appearance is validated as known Bloub shape/color IDs, backfilled from UUID bytes, and written once at creation. Root UUIDs are random and child UUIDs derive from their box/name, so retries and renames keep their appearance. Settings can change root title/shape/color; authenticated PATCH endpoints also support child identity. The `box_create` tool accepts each Leti's name and role title, with repeated titles allowed. Runtime teammate context and box API responses include titles. Preview edits last for the mounted session; authenticated settings persist in PostgreSQL.

`GET /v1/workspaces/{workspace}/letas/box-view?leta_id=&cursor=` returns authorized agent identities, boxes, permission edges, schedules and runtime summaries. Management permission is required per Leta, independently of workspace ownership. The endpoint batches topology reads and paginates 20 root candidates; no system prompts are included. Each root's child topology is currently returned together; very large teams need a per-root graph loading strategy before scaling that surface.

The existing runtime writes its heartbeat summary about every six seconds; a running agent with a heartbeat newer than 15 seconds is Working, and a stale heartbeat is Unknown. Queued ordinary input, idle, paused, error and inactive states remain distinct. SSE connection/lifecycle active is never labelled as working or online. Box queries refresh on runtime events plus five-second polling; global Box roots outside the selected Leta rely on polling. Fetch failures retain the topology with an explicit stale notice and Unknown working states; authorization failures hide it. No separate presence service was added. Current tool labels use committed history boundaries and can trail in-flight tool events.

## Storage tabs and conversation files

The nonclosable identity tab shows Personal/Team or agent avatar, name and title. Box All uses Box. Files open in deduplicated closable tabs; folders navigate the base browser. Each storage keeps its tabs and last folder; relative breadcrumbs live inside the content toolbar and collapse middle segments on mobile. The compact text toolbar provides Preview/Code, line/size statistics, wrap, copy, download and save.

Each human–Leta conversation retains its existing stable ID and lazily provisions a private LetFS storage. Creation locks the conversation record and retries deterministic remote IDs. Conversation-derived ACLs grant read/write to the human and root agent while agent-use access remains valid; Activity visibility alone grants no file access. The existing `file_list("/mnt")` refreshes discovery and exposes accessible storages with conversation identity. No new agent tool or appended file inventory was added.

The composer ports OpenBot's native contenteditable editor and DOM editing helpers to React for atomic `:file[label]{name=storage_id/node_id}` chips. Server-validated references retain custom labels plus name/MIME/size/version snapshots. File metadata never grants access. Upload/paste/whole-chat external drop stores files in the conversation root; internal drops link source IDs or offer an explicit copy when the agent cannot read the source. Removing a mention leaves the file in storage. Storage and conversation uploads share one bottom-right Uploads panel with progress, retry and removal. It stays anchored at the bottom right, with one dismiss action and retry on failed rows; it has no collapse control or per-row remove action. No transient upload card/progress renders inside the composer. Pending/error/retry state stays with the originating agent draft; send is blocked until pending files are resolved. `@` searches nested files across accessible storages through existing SearchFiles (first 100 hits per storage); the shared picker browses the rest.

OpenBot's ComposerEditor distinguishes local emission from external draft edits and defers insertion during IME. Ordinary keystrokes update a mutable per-agent draft map without broadcasting React context updates or rebuilding the DOM. The browser owns native typing/undo and composition; agent switches restore the corresponding draft. External mentions insert native noneditable tokens at the saved caret. The placeholder remains `Message <agent name>…`. Copied OpenBot helpers retain the PolyForm Noncommercial 1.0.0 license and required notices in `src/components/agents/openbot/`; commercial use requires its separate license.

File listing refreshes at 15 seconds and storage discovery at 30 seconds in the web app; mutations invalidate the existing queries immediately. This is not concurrent collaborative text editing: LetFS expected-version conflicts preserve the local draft. Authenticated browser-to-gateway and real device IME verification remain deployment checks.

In-app file dragging ports OpenBot’s pointer threshold, hit testing, ghost, cancellation and click suppression from `library-folder-drag.ts`. The shared Storage browser resolves folder/storage drop targets; the Agent Files provider passes dropped files directly to the existing validated attach action when the target is the composer. Internal dragging no longer serializes or reparses HTML5 DataTransfer payloads or reloads nodes from IndexedDB to attach them. OS file drops still use native copy semantics and upload into the conversation root. Browser checks exercise mouse drags and a copy-only native OS file source. Demo storage mutations use a single IndexedDB read/write transaction so simultaneous uploads cannot overwrite one another; versioned file saves retain conflict protection.

## Nested workspace routes

The application uses code-based TanStack child routes and Outlets rather than dispatching every page from `/app` query parameters. Paths identify workspace, agent, main tab, Box scope and storage folder/file; header/sidebar/breadcrumb navigation uses a shared typed destination contract. Agent Chat is `/app/:workspaceId/agents/:agentId`; Overview/Activity/Box are child paths. Leti activity includes its root agent and Leti ID. Storage file tabs use `/storage/:storageId/files/:nodeId`, and browser folders use `/folders/:folderId`. Settings use `/settings/:section`.

The workspace provider stays mounted across these paths, retaining drafts, file tabs/sessions, folder state and per-agent Chat/Activity bookmarks. Path state selects the visible surface, including on Back/Forward and direct reload. Direct file/Leti links insert the selected closable tab. Unknown IDs do not silently display a default resource. Capability guards apply to Activity and Leti views; backend permissions remain authoritative.

Legacy `/app?...` links redirect with replace and retain storage targets. A workspace-level guard protects unsaved file sessions when leaving the workspace, even from another page; same-workspace routing preserves drafts. Browser reload/unload also checks the retained sessions. Vite serves nested links locally; production hosting must return the SPA entry for `/app/*` and `/login`. No production frontend host configuration/deployment is included.

Routing verification: **56 distinct browser checks pass** across routing, agent layout/scroll, Overview/Activity, Box, conversation files/composer, Storage and text editing. The first regression run passed 52 checks and exposed four phone-entry failures; those four pass after correcting `/app`'s initial mobile pane while preserving direct-detail links. Production build, web/E2E type checks and diff whitespace checks pass; lint completes with warnings. Desktop Storage and mobile file-view screenshots were inspected. Signed-in backend browser sessions and production hosting were not exercised for this migration.
