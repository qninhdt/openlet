\# Openlet — Final Upload / Download Architecture

\


\## 1. Upload

\


\*\*Small inline files:\*\* Client → letfs → PostgreSQL (\`nodes\` + \`files\`). Một HTTP transaction, không cần upload session.

\


\*\*Object files:\*\* Client → S3 trực tiếp bằng presigned URLs. Backend chỉ quản lý authorization, upload session, verification và publication.

\


\### API contract

\


\`\`\`http

POST   /filesystems/{fs}/uploads

GET    /filesystems/{fs}/uploads/{id}

POST   /filesystems/{fs}/uploads/{id}/parts

POST   /filesystems/{fs}/uploads/{id}/complete

DELETE /filesystems/{fs}/uploads/{id}

\`\`\`

\


**\*\*Create upload request:\*\***

\


\`\`\`json

{

  "parent_id": "uuid",

  "name": "report.pdf",

  "size_bytes": 104857600,

  "media_type": "application/pdf",

  "mode": "create",

  "checksum": {

    "algorithm": "sha256",

    "value": "..."

  }

}

\`\`\`

\


\`mode\` là \`create\` hoặc \`replace\`; replace yêu cầu expected revision để tránh ghi đè thay đổi đồng thời. Gửi thêm \`Idempotency-Key\` trong HTTP header.

\


**\*\*Create response:\*\***

\


\`\`\`json

{

  "upload_id": "uuid",

  "transport": "multipart",

  "part_size": 8388608,

  "expires_at": "...",

  "state": "open"

}

\`\`\`

\


Với single PUT, response có thêm \`transfer: {url, headers, expires_at}\`.

\


\### Pipeline

\


1\. \`POST /uploads\`: xác thực, kiểm tra destination/quota, tạo session và object key duy nhất.

2\. Backend cấp presigned PUT hoặc multipart part URLs. Client truyền bytes trực tiếp lên S3.

3\. \`POST /complete\`: hoàn tất multipart nếu cần, xác minh object size và checksum bằng cơ chế provider hỗ trợ.

4\. PostgreSQL transaction: kiểm tra lại preconditions/quota, tạo hoặc replace node, ghi \`files.object_key\`, finalize session. Nếu replace, enqueue object cũ vào \`object_deletions\`.

5\. Retry finalize trả lại kết quả đã lưu. Upload bị abort/expire được cleanup bất đồng bộ.

\


**\*\*Upload session states:\*\*** \`open → completing → finalized\`, hoặc \`open/completing → aborted\` khi đã xác định an toàn để hủy. Expiration được biểu diễn bằng timestamp.

\


**\*\*Multipart:\*\*** Sử dụng native S3 API qua Rust \`object_store\`; giữ upload ID và part receipts cần thiết để retry completion. Không tự tính full-object MD5 từ ETag.

\


**\*\*Processor:\*\*** Tái sử dụng upload transport cho generated artifacts, nhưng publication của artifacts thuộc processing pipeline, không phải HTTP upload lifecycle.

\


\## 2. Download

\


\`\`\`http

GET /filesystems/{fs}/nodes/{id}/content

GET /filesystems/{fs}/nodes/{id}/archive.zip

\`\`\`

\


**\*\*Single file:\*\***

\- Inline: letfs trả bytes trực tiếp, hỗ trợ HTTP Range.

\- S3 object: letfs kiểm tra quyền rồi trả \`307\` đến presigned GET URL. Client download trực tiếp từ S3, hỗ trợ Range theo provider.

\


**\*\*Folder ZIP:\*\***

\- letfs duyệt cây trong PostgreSQL.

\- Đọc từng file inline/S3 theo streaming.

\- Dùng \`async_zip\` tạo ZIP incremental, giữ nguyên directory structure và empty directories.

\- Stream ZIP qua Axum HTTP response.

\- Không tạo ZIP tạm trên S3, không background job, không Temporal.

\- Connection đứt thì tải lại từ đầu.

\


\## 3. Object Deletion

\


**\*\*Giữ \`object_deletions\` dưới dạng transactional outbox / durable deletion queue.\*\***

\


\`\`\`text

Delete / Replace / Purge

    → PostgreSQL transaction

    → Enqueue object key

    → COMMIT

    → Temporal-scheduled cleanup worker

    → S3 DeleteObject

    → Hoàn tất deletion intent

\`\`\`

\


Worker phải có retry/backoff, lease chống xử lý đồng thời, kiểm tra object không còn được tham chiếu và không còn upload đang hoạt động. Xóa queue record sau khi S3 đã xóa thành công **\*\*và không còn nguy cơ late write\*\***.

\


Đối với upload candidate từng được cấp presigned URL, giữ thông tin về quyền ghi còn hiệu lực và bảo vệ late/in-flight writes. Không xóa tombstone sớm chỉ dựa trên URL expiration.

\


S3 Lifecycle dùng bổ trợ để abort incomplete multipart uploads; không thay thế durable cleanup của các object chính.

\


\## 4. Database

\


\| Table | Vai trò |

\|---|---|

\| \`nodes\` | Filesystem structure |

\| \`files\` | Content reference, bytes, semantic metadata |

\| \`uploads\` | Upload session, multipart identity, verification, finalize result |

\| \`object_deletions\` | Durable S3 cleanup intents |

\| \`trash_entries\` | Trash/restore metadata |

\


Không dùng generic \`operations\` cho upload/download. Không cần Temporal Workflow cho mỗi upload hoặc mỗi object deletion.
