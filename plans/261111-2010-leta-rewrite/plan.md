Cập nhật 2026-11-13. Đang implementation theo thiết kế đã duyệt: native runtime/API/worker, domain schema, Cloud observability và delivery wiring đã có code. Xem [execution record](execution.md) cho commit boundaries, checks và Redis/Mirage integration sau allowlist đã được người dùng duyệt; shared API E2E 5/5 đã pass; Cloud/deploy acceptance còn lại. ## Kết quả, phạm vi và ràng buộc

Viết mới toàn bộ apps/leta, giữ Leta/Leti, immutable box graph, durable messaging, checkpointed runtime/history/compaction, async HITL, native schedules, Mirage files/search và public events. Archive source/tests cũ chỉ context, không copy handwritten implementation/tests/SQL từ đó, compatibility layer hoặc giữ old tests để ép thiết kế. Fresh database/Temporal namespace, không import data/jobs/histories cũ; database cũ giữ nguyên tới cutover riêng.

Agent có thể luôn bận 24/7 nhiều tháng/năm: activity runtime chạy dài và heartbeat; abefore_model lấy bounded inbox batch, native checkpoint/compaction/pruning giữ working state hữu hạn. Agent/ScheduleChanges Continue-As-New theo native suggestion tại workflow events; bỏ slice 5 phút. Khi runtime đang bận, tái dùng native cancellation có chờ safe checkpoint/cleanup, không yield RPC hoặc SQL flag mới. Không lifetime timeout/manual reset hoặc đợi workload rỗng. PostgreSQL domain, LangGraph context/progress, Temporal orchestration, Redis provisional events/cache, SpiceDB rights.

Thuật ngữ cho implementation mới: workflow HitlRequest, workflow ID hitl/{request_id}, module hitl.py/jobs/hitl.py, bảng hitl_requests/source_kind=hitl, activities open_hitl_request/resolve_hitl_request/apply_hitl_outcome và DTO prefix Hitl. Owning API dùng HTTP JSON + SSE đã chốt; request collection dùng hitl-requests. Không alias compatibility cho thuật ngữ cũ. Human/user vẫn chỉ người dùng/người duyệt; giữ nguyên type HumanMessage của LangChain vì đó là tên thư viện. Archive và hồ sơ implementation lịch sử giữ nguyên để tham khảo, không đổi tên source cũ rồi dùng lại.

Thuật ngữ inbox thống nhất: **inbox notification**, gọi ngắn là **notification** (thông báo), thay tên cũ `digest`. Inbox là hộp thư; message là tin nhắn gốc; summary là bản tóm tắt compaction. Dùng tên này cho new implementation, tool descriptions và owning docs; không đổi lịch sử archive.

## Thứ tự implementation

1. Bắt đầu schema/core/Temporal/runtime/VFS theo thiết kế đã chốt; Mirage/cache và retention MVP không cần hỏi lại. Future purge/expiry ngoài scope. Hoàn thiện HTTP DTO/errors trước API từng feature theo semantics đã duyệt; không cần hỏi từng field/status hoặc chặn mọi implementation. Triển khai shared provisioning/cleanup cùng core owner, gồm backend hiện có, Go/Python/queue config và cắt visibility update. File conflicts/retry horizon, operator access và compaction đã duyệt. Transfer ownership hoãn, không periodic housekeeping. Numerical budgets là cấu hình/tuning. Box/Leti theo boxes.md, streaming theo streaming.md, infra theo system.md.
2. Dùng archive/progress record của core, kiểm actual inventory/dirty tree trước tạo app mới. Chỉ archive thêm nếu có source mới còn active; không ghi đè snapshots hoặc recreate/restore source đã absent. Loại archive khỏi discovery.
3. Viết app mới từng dòng: baseline schema, role config/native generated clients, feature functions, native saver/runtime/Mirage. Giữ schema ownership/constraints đã duyệt.
4. Nối activities/workflows và API; consume generic workspace check/generated Python SDK hiện có và triển khai Leta native graph batch. Dùng core boundary đã bỏ registration RPC/owned-agent scan và đổi workspace.agent, không làm lại phần core đã hoàn tất. Giữ quyền human/owner guard, kiểm một remove/rejoin case: human mất quyền còn agent cùng workspace giữ quyền, agent workspace khác không được cấp quyền. Đồng bộ core owner nếu integration phát hiện contract/config gap; không khôi phục test cũ để giữ policy đã bỏ. Cập nhật affected config/build/exports/CI; không dual serve/dual write, wrappers hoặc generic framework.
5. Chạy focused checks và một shared dependency environment/journey; core suites vẫn chạy khi Leta không deploy. Đo CI elapsed/container starts/handwritten lines riêng, không invent savings.
6. Cutover riêng có backup/restore và stop old writers/schedules; không thay data ở lượt design này.
