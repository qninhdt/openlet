## Implemented

- `leta/schedules.py` validates at/relative/interval/calendar definitions and compiles native specs. Relative at and default interval anchors use `requested_at` carried in the accepted Temporal Update; Local retry never recomputes wall time. Canonical times round upward to native seconds. Calendar fields use the actual SDK defaults, integer/list/range/wildcard and IANA timezone; months are not fixed durations.
- `ScheduleChangesWorkflow` serializes Local SQL definition changes and regular native apply. Deleted coordinators finish; ordinary history rotation drains handlers. Completed delete retries attach to the result and verify root namespace. No new SQL columns, command journals or completion ledger.
- `ScheduleDeliveryWorkflow` reads actual server `TemporalScheduledStartTime` and `TemporalScheduledById`, snapshots current content with a Local Activity, then admits through the shared regular `deliver_agent_input`. Message identity is deterministic for schedule plus nominal UTC instant. Deleted recipients/sources skip; pause blocks new snapshots without retracting admitted ones.
- Direct already-due at delivery uses the **same Workflow ID format as native Schedule actions**, verified from real captured history: `schedule-delivery/<schedule-id>-<UTC RFC3339 timestamp Z>`. Start uses USE_EXISTING/REJECT_DUPLICATE, so metadata edits cannot launch a second snapshot of an existing occurrence. Native apply acknowledges Workflow start without waiting for delivery; pause/delete are not held behind a blocked recipient.
- Native CRUD uses BUFFER_ONE, leaves catchup_window unspecified and preserves consumed one-shot allowance on matching-spec retries/metadata/pause edits. Genuinely changed spec rearms. SDK 1.35.0 rejects creating limited-actions with zero remaining; already-due sources are first provisioned paused with one action, then updated to consumed state before direct delivery. Update never deletes/recreates the native source.
- Common delivery now belongs to `AgentActivities(store, client)` and is always registered, including schedule-only workers. `HumanActivities` inherits it; existing controlled failure overrides remain usable. Inbox constructor callers and both owned crash-worker fixtures were updated.
- Store supports read, patch, tombstone, scoped lists and snapshot admission. Root manages owned schedules; Leti manages its own target only. Box teardown sends typed schedule deletion commands even while the root/box is deleting.
- Five runtime tools are registered: create/list/get/update/delete. Typed at/interval/calendar tool input runs through the real LangGraph tool parser. Explicit null end_at clears cutoff; omitted fields survive. A single get returns at most ten native next times plus an explicit forecast status; definitions remain available when Temporal is unavailable.
- `calendar_occurrences` returns complete globally sorted `(start, end]` results or a clear too-large/unavailable error. It uses the generated `list_schedule_matching_times` RPC, maximum 366 days/32 definitions/1000 results/32 RPCs/concurrency four. Exact-1000 native responses continue from their exact last instant with unchanged end; no one-second skip and no public cursor/partial result.
