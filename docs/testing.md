# Testing

Use native owner checks and one small API E2E stack. Tests do not import archived implementations, duplicate an entire API matrix or call paid providers in CI.

```sh
make check test
OPENLET_TEST_DATABASE_URL='postgres://…' make integration
scripts/e2e.sh api
```

`make format` applies gofmt to Go, Ruff import sorting/formatting to Python, and Prettier to JavaScript/TypeScript. Shared whitespace conventions live in [`.editorconfig`](../.editorconfig); formatting does not depend on an editor configuration. `make check` checks those formats and runs Go vet, Ruff lint, Pyright strict, Buf, TypeScript and shell syntax checks. Pyright includes Leta, ingest, SDK, their tests and operational scripts; generated clients and archive are excluded. Async gRPC typing is generated by `make generate` alongside the clients.

Focused Go tests cover text/path/idempotency behavior; Python tests generate their Office inputs and check conversion/layout, enrichment evidence, index context, input bounds and telemetry. Public boundaries use concrete types rather than unparameterized dictionaries. The integration-tagged LetFS test requires an isolated, migrated, backed-up database and proves SQL invariants. Never point it at old or production databases.

[Playwright](../e2e/playwright.config.ts) has API service journeys in one shared dependency stack. `scripts/e2e.sh api` runs them, including Leta; extra Playwright file/grep arguments are forwarded. API uses APIRequestContext.

The five API journeys cover:

- JWT verification, trusted-header stripping, ProtoJSON errors and internal RPC isolation.
- Invitation acceptance/member limit, member storage, viewer grant/revoke and workspace deletion.
- Text/version/idempotency, quota rejection, copy, streamed ZIP, trash and restore.
- XLSX through real CPU/IO Temporal workers, readonly artifacts, upload receipt replay/conflict, real Qdrant hybrid search and exact blob download. The embedding fixture ranks keyword evidence below the root README; BM25/RRF must recover it as the first result.
- PDF and DOCX uploads through the Datalab SDK's multipart and polling flow, with WireMock responses and Markdown artifact assertions.
- Leta provisioning, tools and persistent Mirage session, SSE bootstrap, boxes, HITL, owner-independent schedule delivery and workspace cleanup.

PostgreSQL, SpiceDB, Temporal, RustFS and Qdrant are real dependencies. WireMock serves the Clerk/JWKS, model and Datalab HTTP fixtures. Fresh signing keys live for one run, including Playwright worker restarts. Assertions poll bounded async outcomes with native Playwright tools without fixed sleeps.

[CI](../.github/workflows/ci.yaml) runs on PRs and pushes to main/dev. Path filters select backend checks, contract generation, web checks with Chromium and the shared API integration stack. Selected jobs run in parallel. API E2E reports and browser failure artifacts are available in GitHub Actions. [Release](../.github/workflows/release.yaml) verifies the exact images it subsequently pushes. The local Datalab fixture covers multipart. Production S3 presigned GET needs a separate live check.

The Leta journey covers root provisioning, a native model/tool loop with file effects, bounded SSE bootstrap, box/Leti execution, asynchronous HITL, a native schedule after owner removal and cleanup. Native Python checks cover inferred tool arguments, cancellation settlement, event folding and VFS search paths. WireMock supplies deterministic external model/prompt responses, while LangGraph, Mirage, Redis, PostgreSQL and Temporal run normally. The [execution record](../plans/261111-2010-leta-rewrite/execution.md) distinguishes passing checks from incomplete integration; adding a test does not mean its acceptance has passed.
